# Security Policy — SIPE

## Vulnerability Reporting

**Please do not report security vulnerabilities through public issues on GitHub.**

If you identify a security flaw in any project repository or service (whether in the API backend or associated clients), please report it directly to the responsible team.

---

## How to Report
Send an email to the project security team at:
* **Email:** `sipeforeducation@gmail.com`

To help us triage and understand the nature and scope of the problem more quickly, please include as much detailed information as possible:

* **Type of flaw:** (e.g., SQL injection, JWT flaws, authorization, Cross-Site Scripting, etc.)
* **Affected location:** API endpoints or related source code files.
* **Version/Branch:** Current tag, branch, or commit where the problem was identified.
* **Steps to Reproduce:** Clear, step-by-step instructions for simulating the scenario.
* **Proof of Concept (PoC):** Payloads, cURL requests, or code snippets demonstrating the vulnerability (if applicable).
* **Impact:** Description of how an attacker could exploit the flaw and what data/services could be compromised.

---

## Disclosure Policy

This project adopts the principles of **Coordinated Vulnerability Disclosure**. We strongly urge you to wait for the official fix and the release of a security patch before publicly disclosing any details.

Thank you for helping keep SIPE and our users' data safe!
